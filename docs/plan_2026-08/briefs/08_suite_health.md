# Workstream 8 — Suite-wide health, open items and additional evolutions

**Abstract.** This brief covers everything in the EO-Sat-1 SMO suite outside the six parallel subsystem workstreams: the consolidated register of genuinely-open items (verified against the tree, not against documents claiming "done"), a dead/unwired-code sweep across config, telemetry, commands, events, endpoints and UI, an assessment of the 2,527-test suite and the generic contract tests that would stop the project's recurring defect classes, cross-cutting engineering quality (threading and the tick loop, determinism under time acceleration, breakpoint save/restore completeness, dispatch error handling, and the classroom deploy path), operator and instructor experience gaps measured against what a small-mission control system provides, documentation status with a consolidation proposal for the loose reports in the repo root, and a ranked set of additional evolutions with discrete work packages. The three headline findings are that the simulator is **not reproducible** (no RNG seeding anywhere, and time acceleration changes the physics), that **breakpoint save/restore silently loses the S11 on-board schedule, injected failures, the spacecraft phase machine and eleven other pieces of state**, and that **ground-side limit checking and the entire FDIR fault-propagation and recovery-procedure model are fully specified in configuration and never execute**.

## Test strategy gaps

Current shape: **2,527 test functions** across 12 directories — `test_simulator` 745, `test_mcs` 615, `test_planner` 316, `test_rfsim` 268, `test_acceptance` 234, `test_integration` 139, `test_content` 71, `test_common` 51, `test_e2e_browser` 35, `test_gateway` 25, `test_commissioning` 28, plus 23 loose root files. That is a strong suite by volume. The gap is not coverage of code, it is coverage of **contracts between artefacts** — which is precisely where every recurring defect lives (#36 model↔display keys, #37/#40/#45 config↔dispatch, #47/#68 schema↔wire, O-5 config↔config).

Add these **generic, data-driven** tests; each replaces a class of one-off tests and would have caught named past defects:

1. **`test_parameter_chain.py` — the TM chain closure test.** For every entry in `parameters.yaml`, assert exactly one of: (a) it appears in ≥1 HK SID, (b) it is `on_demand: true` and the S20 handler can read it, (c) it is explicitly listed in a `DERIVED_ONLY` allowlist with a reason. Then assert every SID member is produced by a booted engine after N ticks, and every parameter named in `limits.yaml` or `s12_definitions.yaml` is reachable by (a) or (b). *Catches: #5, #36, finding 12, finding 13.*
2. **`test_limits_are_live.py`.** Boot an `MCSServer`, feed a synthetic HK packet that violates each band in `limits.yaml`, assert an alarm appears in the journal. *Catches O-9 and prevents its recurrence.*
3. **`test_config_keys_have_consumers.py`.** Walk every YAML under `configs/eosat1/`, collect leaf keys, assert each is either referenced in `packages/`/`tools/` source or listed in a documented `KNOWN_UNUSED` allowlist. Pair it with `model_config = ConfigDict(extra="forbid")` on the `smo_common` schemas so the *other* direction (consumer reads a key no config defines) fails at load. *Catches: #51-class drift, `ground_segment`, `platform_idle_power_w`, `frequency_hz`.*
4. **`test_catalogue_dispatch_bijection.py`.** For every entry in `tc_catalog.yaml`, dispatch a synthetic packet built from its own `fields` against a mock-subsystem dispatcher and assert ≥1 handler is driven; and assert every branch reachable in `_route_*_cmd` has a catalogue entry. I ran this statically today and it is currently **clean for all 93 S8.1 funcs and all 14 services** — pin it before it rots. *Catches: #37, #38, #45, #80.*
5. **`test_procedure_refs.py`.** Assert `activity_types.yaml.procedure_ref` resolves to a `procedure_index.yaml` id **and** that the reverse `runnable:` link (where present) names the same activity, and that the procedure's `name` is semantically plausible for the activity. *Catches O-5 today.*
6. **`test_event_catalogue_emissible.py`.** Every event in `event_catalog.yaml` must be emittable — assert its id or name appears in an emission call site, or is allowlisted. *Catches O-11.*
7. **`test_endpoint_reachability.py`.** Enumerate registered aiohttp routes per server; assert each is referenced by a UI asset, another package, a tool, or an `INTENTIONALLY_API_ONLY` allowlist with a reason. *Catches #13, #16, O-12, O-13, O-14 — and would have caught them the day they were introduced.*
8. **`test_breakpoint_round_trip.py` (property test).** Boot an engine, tick to a randomised but seeded state (schedule loaded, failure injected, dump in progress, HK SIDs toggled, phase = bootloader), save, perturb everything, load, then assert a deep-equal on a canonical state dump. Currently `tests/test_breakpoint_orbit.py` and `test_breakpoints.py` check specific fields; a whole-state property test is what finds the eleven attributes listed in B-2.
9. **`test_determinism.py`.** Same seed + same `t0_epoch` + same command script ⇒ byte-identical parameter trace after N ticks. Then a second case: the same *scenario* at speed 1 and speed 10 must agree on integral quantities (end-of-orbit SoC, eclipse entry time, total heater energy) to within a stated tolerance. This test will fail today; that is the finding.
10. **Retire the strict-xfail pattern once decisions land.** `test_s19_rules_content.py:279` is used correctly (a visible, non-red gate on a domain decision) — but three strict-xfails have now been open across two sessions. Add a CI rule that a strict-xfail older than one release fails the build, so the gate cannot become permanent furniture.

Also: `tests/test_e2e_browser` (35 tests) is the only thing defending the 9,088-line inline-JS `index.html`. Every JS defect in the #63–#79 batch was found by a human reading the file. Recommend extracting the JS to modules (see evolutions) so it can be unit-tested at all.

## Engineering quality findings

**A. Threading and the tick loop**

- **A-1 (Major) — the N-2 snapshot contract is only half implemented.** `get_state_summary()` correctly returns the published snapshot (`engine.py:2808-2820`), but `get_instructor_snapshot()` reads `self.orbit.state` **live** at `engine.py:2958` and then calls `_get_all_subsystem_states()` (`:3007-3032`), which iterates every subsystem's `_state.__dict__` on the aiohttp thread while the tick thread mutates it. Worse, at `:3020` `dict`/`list` values are stored **by reference** — `power_lines`, `rw_speed`, `image_catalog` — so `json.dumps` on the response thread can hit `RuntimeError: dictionary changed size during iteration` against a growing `image_catalog`, and a caller mutating the response would corrupt the simulation. The instructor console is the display most likely to be open during an anomaly. **Fix:** build the instructor snapshot inside `_publish_snapshot()` with deep copies.
- **A-2 (Minor) — `if True:` still wraps the entire tick body** at `engine.py:1077`, a 400-line indentation artefact (DI-06). Harmless, but it is the first thing a student sees when asked to read the tick loop.
- **A-3 (Major) — breakpoint save/load still runs inline on the aiohttp thread** (roadmap X-6, never done): `BreakpointManager.save()/load()` reassign `eng.params`, `eng._sim_time` and every `model.set_state()` with no coordination with `_tick_once`. A load landing mid-tick produces a spacecraft state with no physical cause — the worst possible thing to hand a student mid-exercise. **Fix:** route through `instr_queue` with a future, as the WS path already does.

**B. Determinism and reproducibility**

- **B-1 (Critical) — no RNG seeding anywhere.** `seed(` has zero hits in `packages/`. The global `random` module is used for separation tumble rates (`engine.py:2621-2623`), star-tracker star counts (`aocs_basic.py:441`), CSS illumination, magnetometer noise, gyro bias and attitude random walk (`aocs_basic.py:508-782`), and failure flicker timing (`failure_manager.py:100,157,160`). Every run of every exercise differs, the RNG state is not in the breakpoint, and N-5's `t0_epoch` fix therefore did **not** deliver reproducibility. **Fix:** one `random.Random` instance per engine, seeded from `simulation.yaml` (`seed: 20260310`), threaded into the models, and saved/restored in breakpoints.
- **B-2 (Critical) — breakpoint save/restore is materially incomplete.** 93 engine attributes are assigned; `breakpoints.py` touches ~12. The following mutable state is **lost on load** and each has an operational consequence:
  - `_spacecraft_phase` (`engine.py:326`) — the authoritative bootloader gate at `engine.py:1505` and `:1533`. Param `0x0129` *is* restored, so after a load the displays and the gate disagree. Save in bootloader, boot the app, reload ⇒ the console says bootloader while application commands are accepted.
  - `_tc_scheduler` — no `get_state`/`set_state` at all (`tc_scheduler.py:52`). **The entire S11 on-board time-tagged schedule is destroyed by a breakpoint load**, which breaks the exact workflow #44–#47 were fixed to enable.
  - `_failure_manager` and `_scenario_engine` — no state methods. Injected failures and running scenarios are lost, so "save → inject → compare" only works in one direction.
  - Dispatcher-owned `_s12_definitions` (enable flags **and** delta baselines), `_s19_definitions`, `_s19_enabled_ids`, `_s13_transfers` — an in-flight S13 transfer and every commanded monitor enable/disable revert.
  - `_current_load_shed_stage` and `LoadSheddingManager._stage` — reset to 0 while the restored power lines are still shed.
  - `_prev_in_contact`, `_prev_in_eclipse`, `_prev_aocs_mode`, `_prev_obdh_mode`, `_prev_payload_mode`, `_prev_active_gs`, `_in_contact` — edge-detector state. On the first tick after a load the whole set re-fires: spurious AOS, eclipse-entry and mode-change events in the log.
  - `_dump_pending`, `_dump_active_stores`, `_dump_byte_budget`, `_rt_pending` — an in-progress S15 dump and the rate-pacing backlog.
  - `_sep_timer`, `_sep_timer_duration`, `_auto_tx_remaining`, `_fdir_safe_active`, `_fdir_emergency_active`, `_override_passes`, `tm_builder` sequence counters.
  **Fix:** invert the design — a `get_state()`/`set_state()` protocol that every stateful component must implement, plus the property test in gap 8, plus a registry so a new component without state methods fails the test rather than silently losing state.
- **B-3 (Critical) — time acceleration changes the physics.** `_run_loop` computes `dt_sim = dt_real * self.speed` (`engine.py:1043`) and hands it straight to `_tick_once`. At ×60 the models integrate 60-second Euler steps: battery, thermal RC, heater hysteresis, wheel dynamics and the S12 delta baselines all give different answers than at ×1. Compounding it, process noise is scaled **linearly** in `dt` (`aocs_basic.py:670-679`, `random.gauss(0, 0.001) * dt`) instead of √dt, so the random-walk variance is off by a factor of `speed`. "Speed it up to reach the eclipse" is the normal student workflow, so this is not a corner case. **Fix:** sub-step the tick — `n = ceil(dt_sim / dt_max)` with `dt_max ≈ 1 s` from config — and fix the noise scaling. Rate control at `:1056-1060` also has no drift compensation, so ×1 is not real-time under load; document that sim time is authoritative.

**C. Error handling at dispatch boundaries**

- **C-1 (Major) — `dispatch()` still signals errors by side-channel** (roadmap X-7, never done). `engine.py:1601-1603` resets `dispatcher._last_error`, `_last_error_code`, `_last_exec_fail` before each call and inspects them after (`:1613-1637`). With three sources of nested dispatch now live — S11 release, S19 event-actions, S18 OBCP steps — an inner command clobbers the outer command's flag, and the outer command reports the inner one's outcome. Defect #87 built excellent plumbing on top of a mechanism that is not reentrant. **Fix:** return a result object; ~5 call sites, all acceptance-covered.
- **C-2 (Major)** — `_reject_tc` (`engine.py:1443`) is now the single acceptance-refusal funnel and is good; the execution-start path (O-4) is the remaining asymmetry.
- **C-3 (Minor)** — DI-17's 160 broad `except Exception` sites remain; several discard silently (`breakpoints.py:37,49,60,71` swallow per-subsystem save failures with a `warning` and then save an *incomplete* breakpoint that loads without complaint). **Fix:** a failed subsystem save must fail the whole save.

**D. Startup / shutdown / classroom path**

- **D-1 (Major) — `start.sh` launches 8 services with `sleep 2` and no readiness check.** If `smo-simulator` dies on a bad config, MCS and Planner still come up and show an empty, plausible console. `wait` (no args) at the end waits for *all* children, so a dead simulator does not stop the suite — the exact "looks like a spacecraft symptom" failure N-1 was meant to eliminate, one layer up. **Fix:** poll `/api/state` before starting dependants; abort with a clear message.
- **D-2 (Major) — the `--public` banner is untrue.** `start.sh:229-233` prints "LOCAL mode: services bound to loopback where supported", but the simulator (`smo-simulator/server.py:43,44,54`), MCS (`smo-mcs/server.py:1001`) and planner (`smo-planner/server.py:437`) hard-code `"0.0.0.0"` unconditionally. Only the three tool viewers honour `--public`. Same class as #90. **Fix:** honour a `--host`/`SMO_BIND` in all three, or correct the banner.
- **D-3 (Minor)** — `start.sh:186-193` runs `pip install sgp4 numpy aiohttp` if Orbit Tools' imports fail. In an offline classroom this stalls, and the failure text blames the wrong thing. **Fix:** vendor into `wheels/` and never reach the network from a start script.
- **D-4 (Minor)** — `start.sh:222` prints `Radio Status: http://localhost:8094` with a hard-coded `localhost` even under `--public`, unlike every other line which uses `$ACCESS_HOST`. Live instance of the defect #90 pattern.
- **D-5 (Minor)** — no shutdown hook closes the MCS `TMArchive` SQLite handle (`server.py:365-366`); combined with `prune()` never running, a term's archive plus WAL accumulates inside the *config* tree by default (DI-28's "runtime data in `configs/`").

## Operator experience gaps

Ranked by what a small-mission control room would notice missing first. Excludes the parallel workstreams' areas.

1. **Parameter history and trending — there is none.** The MCS has live plots only. A real MCS's most-used feature is "show me this parameter over the last 12 hours", and the data, storage and query API already exist (`TMArchive` + four `/api/archive/*` endpoints, finding 7). This is the single largest capability-per-effort gap in the console. Add a trend page: pick parameters, pick a window, overlay limit bands, mark eclipse and contact arcs.
2. **Ground limit checking and a limit-status colour scheme (O-9).** Today a parameter goes red only if the *spacecraft's* S12 says so. 29 limited parameters have no S12 definition, so a student watching bus current, per-line currents, gyro temperature or GPS PDOP gets no visual cue at all. Every real MCS colours on ground limits.
3. **An alarm *system*, not an alarm list.** Missing: acknowledge-with-persistence (`acknowledge_alarm` unused), unacknowledged-alarm counter in the header, alarm severity filter that survives reload, audible/visual "new alarm" cue, and alarm-to-procedure linkage ("this alarm ⇒ run CTG-001").
4. **Mission-plan visibility in the MCS (X-1).** The planner exposes `GET /api/schedule`; nothing in `smo-mcs/src` requests it. A student plans a pass then loses sight of it, and there is no execution feedback loop (`ActivityState.EXECUTING/COMPLETED` are never set).
5. **Imaging geometry on the planner map (O-8).** Targets, swath, sub-satellite track, elevation-mask cone, illuminated/eclipsed arcs. Opportunity selection is a geometry argument and there is currently no geometry on screen.
6. **A working FDIR/autonomy picture (O-10/O-11).** The FDIR window (#76) shows S12 transitions, S19 firings and command rejections — good — but the fault-cascade model and the 10 recovery procedures behind it never run, so the "what is the spacecraft doing about it" half of the display can never populate.
7. **Situational-awareness header.** Missing at a glance: time-to-AOS/LOS with station name, current data-rate tier vs commanded tier (the parameters exist but are in no SID — finding 13), on-board store fill, unacked alarm count, sim speed, and a clear LIVE/STALE indicator for the whole console (per-plot staleness was fixed in #65; the page-level one is still absent).
8. **Instructor controls.** `POST /api/ground-time` exists with no control (finding 18). Also missing: a one-click "restore known-good baseline", a scenario timeline/scrubber showing what has fired and what is queued, and a student-visible vs instructor-visible split of the event log.
9. **Command stack / command history.** The verification log exists per-session and is not archived (`store_command` unused, finding 4). No post-exercise "what did this team send, when, and what came back" — which is the debrief artefact an instructor most wants.
10. **Procedure execution visibility.** `/api/displays/procedure-status` is headless (O-13); `proc.progress`/`current_step`/`total_steps`/`state` (`0x0900-0x0903`) are defined and unreachable (finding 12).

Deliberately **not** recommended: a 3D attitude visualiser, a full XTCE-driven display builder, or a second "wide" wall display. The first two are large; the third already exists as a divergence liability (finding 16).

## Proposed additional evolutions

Ranked. Each justified against the teaching mission.

1. **Seeded, sub-stepped, reproducible simulation (B-1 + B-3).** *Effort M.* Without it no exercise is repeatable, no worked example is checkable, and nothing timing-dependent can be graded. Everything else in the teaching argument rests on this.
2. **A state-ownership protocol with an enforced round-trip test (B-2).** *Effort M.* Save → inject → restore → compare is the core teaching workflow; today it silently loses the on-board schedule, injected failures, the phase machine and the shed stage.
3. **Wire ground limit checking + the trend/archive page (O-9, O-12, gaps 1–2).** *Effort M.* Two of the three most-used features of a real control room, both already 80 % built and unreachable.
4. **Make FDIR actually run (O-10, O-11).** *Effort M.* The course is FDIR-centric; a fault-propagation model that never propagates and ten recovery procedures that never execute is the largest gap between what the documentation promises and what the tool does.
5. **Extract the MCS JavaScript into testable modules.** *Effort M–L.* 9,088 lines of inline JS in one file is where defects #63–#79 lived, and it is untestable except by browser. Splitting it is also the prerequisite for any further display work and makes the console a legitimate student contribution target.
6. **A "console self-check" page.** *Effort S.* One page that reports: which endpoints have UI consumers, which parameters reach a display, which config keys have consumers, which SIDs are enabled, whether the sim is live. It turns the audits in this report into a permanent, running instrument — and it is itself a good lesson in system observability.
7. **An exercise/debrief recorder.** *Effort M.* Record commands, verifications, alarms, events and operator notes for a session, export as a debrief pack. The archive schema already has the tables (finding 4). Debrief is where operations training actually happens, and there is currently no artefact to debrief from.
8. **Symbolic parameter names in scenarios (roadmap L-4).** *Effort S.* Instructors currently write `condition:` against hex parameter ids. The name→id registry already exists in `subsystems/*.yaml param_ids`. This is the difference between instructors authoring scenarios and not.
9. **One `ground_stations.yaml` (X-11) and one PUS routing table (X-2).** *Effort S–M each.* Both are the single-source-of-truth principle the course teaches in Ch 4, and both are the origin of the project's most expensive defects. Worth writing up as a case study.
10. **S12 delta-monitoring content (X-14).** *Effort S.* All 38 shipped definitions use `check_type: 0`; the delta path is implemented and untaught. "The value is fine, the trend is not" is a core monitoring lesson the shipped config cannot currently deliver.
11. **Delete `files/`, `old_index.html`, `index-wide.html` (findings 15–17, O-17).** *Effort S.* ~9,000 lines of stale parallel implementations that students grep into daily.

**Not worth doing** (say so explicitly): the GNU Radio bridge (#18) — the native DSP path now covers the syllabus after #53–#56; defect #19 — superseded, close it; the cleanup registers #20/#21/#22/#32/#33 as written — fold into the numbered findings above and close them; a config-driven `DisplayEngine` revival (finding 9) unless the display work in evolution 5 is taken, in which case delete `displays/engine.py` and `widgets.py` outright and keep the trending code.
